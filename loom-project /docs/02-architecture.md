## 3. 데이터 흐름도

### 3.1 저장 흐름 (Save Flow)

```
사용자 입력
     │
     ▼
┌──────────┐    이미지 있음?    ┌──────────────┐
│ SaveView │───────────────────▶│ Storage 업로드│
│          │        Yes         │ (이미지 저장) │
└──────┬───┘                    └──────┬───────┘
       │                               │
       │ No                            │ image_url 반환
       │                               │
       ▼                               ▼
┌──────────────────────────────────────────────┐
│           items 테이블에 저장                   │
│  (original_content, content_type, user_id)   │
└──────────────────────┬───────────────────────┘
                       │
                       │ DB Trigger / Webhook
                       ▼
┌──────────────────────────────────────────────┐
│         Edge Function: ai-process            │
│                                              │
│  1. GPT-4o-mini 호출                         │
│     → title, category, tags, summary 생성    │
│                                              │
│  2. 원문을 chunk로 분리                       │
│     → item_chunks 테이블에 저장              │
│                                              │
│  3. 각 chunk에 대해 embedding 생성           │
│     → item_chunks.embedding 업데이트         │
│                                              │
│  4. items 테이블 업데이트                     │
│     → title, category, tags, summary 저장    │
└──────────────────────────────────────────────┘
```

### 3.2 검색 흐름 (Search Flow)

```
사용자 검색어 입력
     │
     ▼
┌──────────────────────────────────────────────┐
│       Edge Function: search                  │
│                                              │
│  1. 검색어 → embedding 변환                  │
│     (OpenAI text-embedding-3-small)          │
│                                              │
│  2. pgvector 유사도 검색                      │
│     SELECT * FROM item_chunks                │
│     ORDER BY embedding <=> query_embedding   │
│     LIMIT 20                                 │
│                                              │
│  3. chunk → item 매핑                        │
│     관련 item 정보 조인                       │
│                                              │
│  4. 결과 반환                                │
│     (매칭된 chunk + item 메타데이터)          │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│            검색 결과 리스트                    │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 매칭된 chunk 텍스트 (하이라이트)        │  │
│  │ 제목 | 카테고리 | 태그                 │  │
│  │ [복사] [상세보기]                      │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

## 5. API 엔드포인트 설계

### Edge Functions

| 함수명 | 메서드 | 설명 |
|--------|--------|------|
| `/ai-process` | POST | 아이템 AI 처리 (제목/태그/카테고리/embedding) |
| `/search` | POST | 자연어 검색 |
| `/admin/stats` | GET | 관리자 통계 |
| `/admin/users` | GET | 사용자 목록 |
| `/admin/push` | POST | 푸시 알림 발송 |

### Supabase Direct (iOS SDK)

| 테이블 | 작업 | 설명 |
|--------|------|------|
| items | CRUD | 아이템 저장/조회/수정/삭제 |
| item_images | CRUD | 이미지 메타데이터 관리 |
| collections | CRUD | 컬렉션 관리 |
| collection_items | CRUD | 컬렉션-아이템 연결 |

## 7. 확장성 고려

### 현재 (MVP)
- Supabase Free/Pro 단일 인스턴스
- Edge Function 기본 제공량

### 성장기 (사용자 10,000+)
- Supabase Pro 플랜 업그레이드
- Edge Function 동시성 증가
- 이미지 CDN 최적화
- Embedding 캐시 레이어 추가

### 대규모 (사용자 100,000+)
- 전용 PostgreSQL 인스턴스
- Redis 캐시 레이어
- 이미지 처리 전용 워커
- 검색 전용 벡터 DB (Pinecone/Weaviate) 분리 고려
- 멀티 리전 배포
